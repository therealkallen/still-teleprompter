## 关闭故障调查与修复（2026-10-13）

- 症状：旧版点击关闭后窗口仍在，无法切换到新版。
- 根因：`onCloseRequested` 会在回调正常完成后调用 Tauri `destroy()`；配置仅允许 `close()`，缺少 `core:window:allow-destroy`。原先的回调在保存成功后再次调用 `close()`，触发第二次关闭事件，最后销毁因权限不足被拒绝。
- 复现：使用安装的真实 `@tauri-apps/api/window` 实现和官方 mocks，按项目 capability 限制 IPC。修复前成功保存后销毁次数仍为 0，回归测试失败。
- 修复：补齐仅属于 main 窗口的销毁权限；回调等待保存成功后由 SDK 完成关闭，不再重新请求关闭。保存中重复点击暂时拦截，保存失败保留窗口并允许重试。
- 验证：3 项关闭回归测试通过，分别覆盖正常保存后关闭、保存未完成时重复点击，以及保存失败后重试；全部 18 项前端测试和类型检查通过。
- 旧进程处理：用户确认没有新修改并明确授权关闭；核实进程名、完整路径与 PID 后结束旧版进程，随后确认已退出。没有结束其他进程，也没有修改稿件文件。
- 验证边界：关闭协议和权限在真实 SDK 加官方 mocks 的测试中验证，尚未通过 Windows 桌面交互重测。调查状态为 DONE_WITH_CONCERNS。
- 项目学习：Tauri `onCloseRequested` 的 SDK 会自动调用 `destroy()`，即使应用只显式调用 `close()`，拦截关闭的窗口也必须具有 destroy 权限。退出回调应等待保存后正常返回，避免重入关闭事件。
