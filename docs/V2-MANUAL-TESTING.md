# V2 真人 / Teams 验收清单

先退出 1.0.2，备份 `%APPDATA%\com.still.teleprompter\workspace.json` 和 `.bak`，完整解压 V2 文件夹，运行 Still.exe。确认旧稿件、书签、界面语言、外观、阅读位置保留，捕获排除仍开启。不要只复制 exe。

## 每轮演讲记录

定时模式独立检查：设置 60、240、600 字/分钟，使用已知正文长度的稿件记录对应段落推进时间；章节和提示不计字数，英文按字母计。检查不同字号、窗口宽度与提示显隐。手动滚轮/按键/导航/搜索后必须暂停，继续应从当前视口推进；末尾停止、空稿禁用开始、最小化暂停、重启不自启。Auto 切到 Timed 后麦克风和语音进程应释放。

记录 Windows/CPU、麦克风类型、稿件长度、识别窗口/间隔、会议应用、样本日期和语言。每秒人工标注实际朗读段落，对照提词器位置，计算正确或相邻段落比例；记录实际跟读延迟和每次远跳。测试记录不要包含会议信息或音频，除非演讲者另行明确同意。

1. 选择 Auto，但不点开始：Windows 麦克风使用状态应保持未开启。关闭重开后也不应自动监听。
2. 设置选择麦克风，回阅读点开始。等待加载，朗读中文稿、英文稿及同一句中英混合稿，每类至少 5 分钟。
3. 用 Finance AI、Copilot、RAG、KIC、Invoice Registration、Internal Control、Power Automate；用正常速度、停顿和非母语发音。
4. 小幅省略和插入「嗯」「呃」，观察相邻段落定位和 38% 阅读区。较大改写应 Holding。
5. 回答一个不在稿件中的问题 30 秒：视口应保持；恢复正文后应在可靠匹配时跟读。
6. 跳到远处独特段落：先 Holding，多次识别确认后才可跳。重复、泛化段落应继续 Holding。
7. 用滚轮、滚动条、方向键、Page Up/Down、Home/End、工具栏、全局导航、快速搜索、章节及书签跳转：即时暂停，后续语音不应拉回旧位置。
8. 在新位置点恢复或 Ctrl+Alt+Space：应从当前可见阅读位置重新匹配，停止前的旧语音不能触发移动。
9. Auto 中暂停：ASR 可继续监听，滚动保持。点停止、切回 Manual 或关闭程序：麦克风和 Python 子进程应释放。
10. 进入编辑/设置/导航：跟读暂停。修改稿件、切换稿件后显式恢复，避免旧稿件结果影响新稿件。

## Teams、设备与窗口

- Teams 同时开启同一麦克风，PowerPoint 正常演示。分别检查内置、USB、蓝牙输入；遇独占模式占用，应错误提示而不崩溃。
- 拔出输入设备，观察 Error 与手动阅读仍可用。重插后刷新设备，再开始；不自动重启监听。
- Windows 权限拒绝、没有输入设备、模型/词表缺失、Python 或 ONNX Runtime 缺失：检查错误与重试。
- Windows 捕获排除始终开启：全屏共享、窗口共享、会议录制、不同外观、移动缩放、进入设置；从独立接收端及录制回放验证。
- 快捷键在 Teams 有焦点时控制暂停/恢复；修改组合并验证冲突报告，不影响原有五个动作。

## 两小时稳定性与分发

- 连续运行 120 分钟，每 5 分钟记录 Still.exe、WebView2 进程组及 python.exe 的工作集、私有内存和 CPU。
- 中途进行停顿、离稿、手动干预、暂停/恢复、切换手动/自动和一次设备重新连接。
- 检查无渐进内存增长、无排队延迟增长、控件与拖动流畅。分别报告模型进程及总应用占用。
- 在干净 Windows 10/11 x64 机器解压测试包（需要 WebView2），不依赖开发机 VoiceFlow 路径或系统 Python。
- 独立检查 ZIP 字节数与完整解压字节数，必须包含所有模型/运行库；上限 500 MB，目标约 300 MB。

验收目标均为待测目标：正常阅读准确或相邻段落 ≥95%，典型响应约 1–3 秒，15–30 分钟标准演讲零未确认远跳，两小时无崩溃或渐进内存增长。逐项填写真实结果，未测试不得写通过。
